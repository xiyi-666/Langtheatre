## 范围

本轮针对自动原文抽检中的两份问题稿：7.5 的包装实验讨论、8.0 的冰川讲座。验证语言自然度、事实衔接和专业表述，不对官方 IELTS 难度、题目难度分布或 TTS 音频作认证。

## 实现

- 生成阶段加入时间与设备、对象与数量、比较基准、观察与推断四类事实核对，保留词数、人物、自然表达和原有理解深度要求。
- 听力专项 Part 3 / Part 4 冻结原文前必须返回四项结构化审核。缺项、非法状态或无实质说明均返回审核格式错误；任一细项 FAIL 都覆盖顶层的 approved=true。
- 每篇原文最多一次语义修订，必须携带完整原稿和具体缺陷；修订需同步所有关联表述，再审核全文。仍有缺陷则拒绝进入出题。
- 日志记录章节、审核轮次及格式异常，不记录原文或认证信息。私有测试保存四项意见；无效 JSON 仅保存长度、结束原因及 token 数等诊断元数据。
- 审核输出预算由 1200 调整为 3000 token，允许输出四项理由；提示中同时限制解释长度。没有增加无限重试或失败兜底。

整卷模拟考试沿用其原有审核入口；共用生成提示也获得上述事实约束，新增结构化原文门禁位于听力专项流程。

## 检验方法

使用本地配置的真实模型处理原来的完整自动稿，调用生产的 `reviewAndRepairListeningSource`，不手工润色、不替换主题、不把外部复核结果偷偷写入模型输入。

随后通过单独请求进行文本复核：仅给标题及脚本，不给目标档位、生产审批或修订理由。复核仍使用同一个配置模型，属于独立请求，并非不同模型或专业考官评审。

真实请求失败记录完整保留。7.5 在开发中遇到两次审核格式异常以及一次请求超时；这些都不计为通过。格式异常首两轮的旧采集器未能保存无法解析的正文，不能事后断言异常一定由输出截断导致。已补齐安全诊断，统一输出 schema，并增加显式测试直连选项，避免依赖可能被 `.env` 覆盖的代理环境变量。
